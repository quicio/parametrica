# Parametrica — auditoría técnica y de producto

Fecha: 2026-11-04
Estado: auditoría de solo lectura. No se modificó código de producción.

## Resumen

Remediación aplicada: `2026-11-04-remediation-hardening` resolvió los
hallazgos P0/P1 de IDs, New Document, fixture e2e, advisor y cifras de
documentación. Los puntos de mantenibilidad y producto siguen abiertos.

El proyecto está sano: arquitectura coherente, suite amplia y cero
vulnerabilidades reportadas por `npm audit`. Los riesgos principales no están
en el motor geométrico, sino en:

- higiene de IDs persistentes;
- seguridad al reemplazar el documento desde Start With / New Document;
- drift de documentación y fixtures de test;
- tamaño y acoplamiento de algunos módulos de UI;
- límites conocidos de fabricación.

No hay cambios OpenSpec activos. Una remediación posterior resolvió los riesgos de IDs, New Document, fixture de e2e, advisor y cifras de documentación.

## Fortalezas

- El core matemático es DOM-free y testeable en Node.
- Los contratos de geometría, espacios y mappings son explícitos.
- La arquitectura de registries permite añadir generadores, operadores y
  passes sin tocar el motor.
- La separación geometría → teselación → render → export está bien respetada.
- Instance Layers reutiliza el modelo de capas existente y no creó un scene
  graph paralelo.
- Start With usa previews derivadas y no bloquea la elección si fallan.
- Hay tests de píxeles, determinismo, export, superficie, instancias y
  accesibilidad básica.
- La suite pasa completa y el build no emite warnings.

## Hallazgos prioritarios

### P0 — Riesgo de colisión de IDs de capa

`src/core/document.js` usa un contador global `layerCounter` para generar IDs:

```js
layerCounter++;
id = `layer-${layerCounter}`
```

El contador no se reconcilia con los IDs existentes al restaurar una sesión o
importar un documento. Ejemplo de riesgo:

```text
sesión cargada: layer-2
nueva capa:    layer-2  ← colisión
```

Esto puede romper:

- resolución de `source.layerId` en instance layers;
- `layerResults` y búsquedas por ID;
- caches y picking;
- selección de la capa activa.

`normalizeLayerIds` corrige duplicados al sanitizar, pero no evita que vuelvan
a generarse en runtime.

**Mejora recomendada**

- Generar IDs únicos consultando el documento (`nextLayerId(document)`), no un
  contador global.
- O sembrar `layerCounter` con el máximo/IDs existentes al sanitizar.
- Añadir test de sesión restaurada con IDs altos y creación posterior.
- Hacer lo mismo para `createInstanceLayer`.

### P0 — Reemplazo de documento sin confirmación

Start With / New Document reemplaza el documento actual y guarda la sesión
inmediatamente. Cancel protege el caso normal, pero un usuario puede elegir una
tarjeta por accidente y perder el estado actual.

El historial permite undo en memoria, pero la sesión ya apunta al documento
nuevo y no hay checkpoint automático.

**Mejora recomendada**

- Confirmación breve al reemplazar un documento existente, o
- un botón “Save current as preset” dentro del chooser, o
- un checkpoint automático etiquetado `Before new document`.

### P1 — IDs de superficie no deterministas

`src/generators/parametricSurface.js` genera IDs con `Date.now()`:

```js
id: `parametric-surface-${Date.now().toString(36)}`
```

La geometría es determinista, pero los IDs de Surface no. Esto no rompe
Instance Layers porque sus IDs se derivan del layer y del índice, pero debilita
la promesa de reproducibilidad y complica debugging/caches.

**Mejora recomendada**

- IDs deterministas por contenido, índice o contador por documento.
- Test que compare IDs de dos evaluaciones cold con el mismo documento.

### P1 — Fixture de sesión de e2e frágil

`playwright.config.js` usa `e2e/session-state.json` para que los tests
existentes arranquen con una sesión válida. Ese fixture contiene un documento
completo serializado.

Riesgo: cualquier cambio de defaults (ya pasó con el stroke 0.5) deja el
fixture obsoleto y produce fallos difíciles de leer.

**Mejora recomendada**

- Generar el fixture en un `globalSetup` o en un script antes de e2e.
- O sembrar solo lo mínimo y mantener un test explícito de defaults.
- Evitar que el aviso “Restored last session” contamine tests que no lo prueban.

### P1 — `ai/offline.js` todavía asume generador en la capa

Hay dos accesos directos:

```js
layer.generator.id
Generators.get(layer.generator.id)
```

El panel Advisor está deshabilitado para instancias, pero una llamada
programática o un flujo futuro puede pasar una capa de instancia y lanzar un
error.

**Mejora recomendada**

- Usar un resolver explícito (`generatorForLayer`) o rechazar instancias con un
  error keyed antes de entrar en el advisor.

## Hallazgos de mantenibilidad

### P2 — `Controls.js` concentra demasiadas responsabilidades

2459 líneas para:

- Layers, Instance, Generator, Params, Equations, Harmonics, Operators
- Looks, Camera, Canvas, Coordinates, Scale, Fabricate
- Style, Render, Overlays, Image, Animation, Timeline
- Mutation, Analysis, Notebook, Advisor, Explore, Evolution, Presets, Export

Cada feature nueva añade condicionales y acoplamiento.

**Mejora recomendada**

- Extraer secciones a módulos por dominio:
  - `ui/sections/layers`
  - `ui/sections/look`
  - `ui/sections/fabricate`
  - `ui/sections/presets`
- Mantener `Controls` como coordinador de secciones, no como implementación.

### P2 — `P5Adapter` y overlays

`P5Adapter.js` mezcla transporte de animación, cámara, escena, referencia,
coordenadas, seams, inspección, Quad y captura.

**Mejora recomendada**

- Extraer `drawQuadView`, `drawCoordinateOverlay` y `drawReference` a módulos
  de render.
- Mantener P5Adapter como backend de p5, no como orquestador de overlays.

### P2 — Test suite monolítica

`test/lab.smoke.mjs` tiene 4857 líneas y ~1233 asserts. Es rápido, pero difícil
de navegar y aislar.

**Mejora recomendada**

- Dividir por dominio manteniendo `node:test` o el runner actual.
- Añadir cobertura al menos de `engine`, `document`, `layers`, `surfaceMapping`
  e `instance-layers`.

### P2 — CSS monolítico

`style.css` tiene 3812 líneas. El overlay Start With añadió ~190 más.

**Mejora recomendada**

- Extraer estilos por componente o usar una convención de secciones más
  estricta.
- Documentar tokens de color/espaciado.

## Hallazgos de documentación

### P2 — README y SPEC tienen cifras obsoletas

README sigue diciendo en secciones intermedias:

- `1924 checks`
- `115 tests`
- `38 groups`

SPEC mantiene un estado de implementación de **2026-10-24** y no refleja
Instance Layers, Start With ni los cambios de fabricación.

**Mejora recomendada**

- Unificar los números en una sola fuente (`package.json`/script).
- Añadir una sección “Current architecture” con Instance Layers, Start With,
  Units y Fabricate.
- Revisar SPEC como documento histórico o actualizarlo.

### P2 — 24 specs con Purpose TBD

Hay 24 specs con:

```text
TBD - created by archiving...
```

No rompe la validación, pero reduce la utilidad del corpus OpenSpec.

**Mejora recomendada**

- Pasada de propósito en las specs más importantes:
  `geometry-pipeline`, `surface-pipeline`, `session-recovery`,
  `fabrication-contracts`, `bundle-performance`, `module-boundaries`.

## Hallazgos de producto

### P2 — Preview de Composition poco legible

La tarjeta Start With de Composition usa una preview de Vortex Stack a 96 px
escalada a 160 px. Se ve densa y borrosa.

**Mejora recomendada**

- Preview dedicada de mayor resolución (192–240 px) o una miniatura vectorial
  simplificada.
- No usar la preview genérica de preset para una composición tan densa.

### P2 — Límites de fabricación

Siguen pendientes:

- self-intersection validation;
- caps/merge;
- reparación;
- CSG/booleanas;
- multi-body;
- 3MF.

Fabricate exporta un solo cuerpo. Es una limitación conocida y bien
documentada, pero es la brecha más grande si el producto apunta a fabricación
real.

### P3 — Look personalizado

- No hay presets visuales de usuario.
- No hay color/grosor por pass.
- Coordenadas 3D del cursor siguen fuera de alcance.

### P3 — Rendimiento de instancias

Benchmark Node con 24 instancias de una superficie 64×32:

```text
primer eval: 196 ms
segunda eval (cache): 3.9 ms
curvas: 2400
puntos: 102400
```

Es aceptable para el límite actual, pero no hay render instanced. Antes de
subir el límite de 24, conviene medir en navegador y añadir un benchmark e2e.

## Hallazgos menores

- `parametricSurface` usa `Date.now()` para IDs.
- `layerCounter` es global y avanza al instanciar presets/previews.
- `GeometryExporter` y `createExportContext` parecen contratos residuales sin
  consumidores claros.
- `StartWithOverlay` no tiene `aria-describedby`; el foco y el trap sí están.
- `session-state.json` inyecta el aviso de restauración en todos los e2e.
- `e2e` mezcla tests de comportamiento con fingerprints de píxeles; está bien,
  pero conviene separar los visuales en un proyecto o tag.

## Plan recomendado

### Sprint 1 — Correctitud y confianza

1. IDs únicos por documento para capas e instancias.
2. Test de sesión restaurada + creación posterior.
3. Resolver IDs deterministas de Surface.
4. Confirmación o checkpoint en New Document.
5. Generar `session-state.json` en test setup.

### Sprint 2 — Mantenibilidad

1. Extraer secciones de `Controls.js`.
2. Extraer overlays de `P5Adapter`.
3. Dividir `test/lab.smoke.mjs` por dominio.
4. Pasada de documentación: README, SPEC, 24 Purpose TBD.

### Sprint 3 — Producto

1. Preview dedicada de Composition.
2. Benchmark e2e de 24 instancias.
3. Presets visuales de usuario.
4. `pass-appearance`.
5. Evaluar Phase 5 Solid foundations si fabricación es prioridad.

## Veredicto

Parametrica está en buen estado para seguir construyendo. La base geométrica y
los contratos son sólidos. Las mejoras de mayor retorno ahora son **higiene de
IDs, seguridad al reemplazar documentos y mantenibilidad de UI/tests**, no más
features geométricas.

Si hubiera que elegir una sola cosa: **arreglar la generación de IDs de capa y
añadir su test de sesión restaurada**. Es barato, elimina un riesgo estructural
y protege Instance Layers.
